# 터미널이 무거워서 직접 만들었습니다 - lmux 개발/홍보기

최근에 **lmux**라는 macOS 터미널을 만들어서 오픈소스로 공개했습니다! 오랜만에 작업한 오픈소스 프로젝트입니다. 

- GitHub: [https://github.com/sooftware/lmux](https://github.com/sooftware/lmux)
- 홈페이지: [https://lmux.dev](https://lmux.dev)

<img src="https://raw.githubusercontent.com/sooftware/lmux/main/assets/screenshots/hero-light.png" width=700>

AI 엔지니어가 갑자기 웬 터미널이냐 싶으실 수도 있는데요, 요즘은 AI 덕분에 필요하다면 뭐든지 직접 만들 수 있는 환경이 된 것 같습니다. 그래서 요즘 같은 시기에는 더더욱 **Why?** 가 중요해졌다고 느낍니다. 이번 글에서는 lmux를 왜, 어떤 기준으로 만들었는지와 공개하면서 겪은 일들을 정리해보려고 합니다.

## 왜 만들었나

요즘 업무 시간 대부분을 터미널에서 보냅니다. 예전에는 터미널 하나를 띄워놓고 썼다면, 지금은 여러 세션에서 AI 에이전트들과 동시에 대화하면서 일합니다. 한쪽에서는 학습 코드를 고치게 하고, 다른 쪽에서는 데이터 분석을 시켜두는 식입니다.

이런 환경이 디었다 보니 [cmux](https://github.com/manaflow-ai/cmux)로 넘어가게 됐습니다. cmux는 AI 에이전트용으로 만들어진 터미널인데, 사이드바에서 어떤 에이전트가 일하는 중이고 어떤 에이전트가 제 입력을 기다리는지 한눈에 보여줍니다. 실제로 잘 썼고, 지금도 좋은 앱이라고 생각합니다.

그런데 cmux를 잘 쓰던 중 문득 이런 생각이 들었습니다.

**'언제부터 터미널이 이렇게 무거워졌지? 그리고 터미널이 뭔데 이렇게까지 무거워야하지?'**

cmux에는 내장 브라우저, SSH 워크스페이스, PR 배지 같은 기능이 많이 들어있습니다. 기능이 많으니 무거워지는 건 당연합니다. 다만 제가 실제로 쓰는 건 사이드바의 세션 목록과 에이전트 알림 정도였습니다. 저는 설정도 거의 기본값 그대로 쓰는 순정파입니다. 😅

쓰지도 않는 기능 때문에 앱이 무거운 게 계속 마음에 걸렸고, 클릭이 가끔 엉뚱하게 먹고, 가끔 앱이 멈추는 등 신경 쓰이는 부분도 하나씩 늘었습니다. 특히 아쉬웠던거 하루에도 몇 번씩 깨지는 한글 입력이였습니다. 그래서 **쓰지 않는 기능은 덜어내고, 꼭 필요한 기능과 그동안 아쉬웠던 부분을 보완한 터미널**을 직접 만들어보기로 했습니다.

이름은 light mux를 줄여서 lmux입니다.

## lmux는 어떤 터미널인가

### 1. 가볍다

lmux에서 제일 신경 쓴 부분입니다. 같은 Mac에서 두 앱에 워크스페이스를 1개, 10개, 20개 열어놓고(워크스페이스마다 셸 2개) 가만히 둔 상태로 측정해봤습니다.

<img src="https://raw.githubusercontent.com/sooftware/lmux/main/assets/bench-scaling.svg" width=700>

아래 표는 워크스페이스 20개 기준입니다.

| | cmux 0.65.2 | lmux (in front) | lmux (in the background) |
| --- | ---: | ---: | ---: |
| 앱 크기 | 242 MB | **25 MB** | **25 MB** |
| 메모리 | 661 MB | **235 MB** | **99 MB** |
| 유휴 CPU | 8.10% | **0.10%** | **0.00%** |
| 설정 개수 | ~200 | **~10** | **~10** |

> M4 Pro에서 lmux 0.0.102와 cmux 0.65.2를 측정한 값입니다. 자세한 측정 방법은 레포의 [BENCH.md](https://github.com/sooftware/lmux/blob/main/scripts/BENCH.md)에 정리해뒀습니다.

제가 가장 중요하게 본 수치는 유휴 CPU입니다. 에이전트 스무 개가 작업을 끝내고 제가 확인할 때까지 기다리는 동안에도, 유휴 CPU가 높으면 배터리가 계속 닳기 때문입니다.

### 2. 에이전트 상태 표시

각 세션이 실행 중인지, 끝났는지, 제 입력을 기다리는지, 실패했는지를 사이드바와 pane 테두리에 표시합니다. `⇧⌘J`를 누르면 입력을 기다리는 에이전트로 바로 이동합니다. 세션을 열 개씩 띄워놓고 일하다 보면 "얘가 지금 나를 기다리고 있었네?"를 뒤늦게 발견하는 일이 많은데, 그걸 줄여줍니다.

### 3. 잘못 보낸 메세지 되돌리기

개인적으로 필요해서 만든 기능입니다. 세션을 여러 개 띄워놓고 일하다 보면 **A 세션에 보내야 할 메세지를 B 세션에 보내는 실수**를 정말 자주 합니다. 그러면 B 세션의 에이전트는 엉뚱한 요청을 받고 열심히 일을 시작하고, 그렇게 컨텍스트가 오염되는게 저는 신경이 많이 쓰이더라고요.

lmux에서는 잘못 보낸 메세지에 마우스를 올리고 `×`를 누르면, 그 메세지를 보내기 전 상태로 돌아갑니다. (아직은 Claude Code에서만 됩니다.) 오늘 정도에 배포될텐데, 메세지를 잘못 보냈는데 파일이 수정된 경우 이 파일들도 원래 상태로 되돌리는 기능도 포함하고 있습니다.

<img src="https://raw.githubusercontent.com/sooftware/lmux/main/assets/gifs/forget-x-light.webp" width=700>

### 4. 껐다 켜도 복원

앱을 종료하거나 재부팅을 해도 워크스페이스, 분할, 폴더가 그대로 복원되고 Claude Code와 Codex 세션도 이어서 실행됩니다. 예전에 닫은 세션은 History(`⇧⌘H`)에서 검색해서 다시 열 수 있습니다. 이 부분도 cmux에서 자동으로 해줬으면 좋겠는데, 제가 쓸때까지만 해도 잘 지원이 안 돼서 직접 만들었습니다.

### 5. 한글 입력

터미널에서 한글을 치다가 글자가 빠지거나 자모가 분리되는 경험을 한 번쯤 해보셨을 겁니다. 저는 그게 너무 불편했어서 이번 작업에서 한글 입력에 특히 신경을 썼습니다. 입력 중에 글자가 빠지거나 깨지지 않고, 온전한 문자가 되도록 많은 신경을 썼습니다.

이외에도 cmux를 쓰던 분들이 쉽게 넘어올 수 있도록 테마, 폰트, 단축키, 열어둔 워크스페이스를 클릭 한 번으로 가져오는 기능도 넣었습니다.

## 만들면서 지킨 것들

### 1. 가벼운 게 우선

만들다 보면 넣고 싶은 기능이 계속 생깁니다. 그때마다 좋은 기능이라도 앱을 무겁게 만들면 넣지 않는다는 기준의 철학을 유지했습니다. 실제로 만들었다가 뺀 기능도 꽤 있습니다. 이 철학이 없으면 그저 cmux의 하위호환일뿐이기 때문에, **light** 하다는 어떻게든 유지해가면서 발전시켜나가보려고 합니다.

만들다가 스스로에게 '굳이?' 라는 질문을 던져서, 아니다 싶어면 다 뺐습니다. 지금은 유휴 CPU가 기준치를 넘는 변경은 CI에서 실패하도록 해뒀습니다.

### 2. 에이전트를 wrapping하지 않기

lmux는 `claude`나 `codex`를 wrapping하지 않습니다. 상태는 Claude Code에서는 hooks로, Codex에서는 Codex가 직접 보내는 신호로 받아오기만 합니다. 프롬프트 되돌리기도 세션 파일을 직접 고치는 게 아니라 Claude Code에 원래 있는 rewind 메뉴를 대신 눌러주는 방식입니다. 그래서 lmux가 있든 없든 에이전트는 똑같이 동작합니다.

### 3. 터미널 엔진은 Ghostty 그대로

터미널 자체는 [Ghostty](https://github.com/ghostty-org/ghostty)의 libghostty를 그대로 씁니다. 렌더링이나 입력 처리처럼 어렵고 중요한 부분은 이미 잘 만들어진 걸 쓰고, 저는 그 위에 사이드바와 에이전트 관련 기능만 Swift로 얹었습니다. Electron이나 브라우저 엔진은 쓰지 않았습니다.

## 어떻게 만들었나

저는 AI 엔지니어라 Swift나 macOS 앱 개발 경험이 전혀 없습니다. 그래서 lmux는 처음부터 Claude Code를 이용해서 만들었습니다. 10월 31일에 개발을 시작해서 11월 5일에 공개했습니다.

어느 정도 만들어진 뒤부터는 **lmux 안에서 Claude Code를 돌리면서 lmux를 개발했습니다.** 스스로 QA를 반복하며 불편한 게 보이면 바로 그 자리에서 고치는 식이었는데, 매일 쓰는 도구다 보니 혼자서 QA하면서도 여러 버그들을 찾을 수 있었습니다.

## 만들었으면 홍보해야지?

기껏 만들었고, 오픈소스로 공개했는데 아무도 존재하는지 모르면 그것만큼 슬픈게 어디있을까요? 그래서 다 만들고 나서는 어디에 어떻게 홍보하는게 좋을지 고민을 했습니다.

### 이전과는 다르다

저는 오픈소스로 스타를 꽤 받아봤습니다. 여태까지 개인 프로젝트로만 스타 수천개를 받았고, 하나의 레포로 1k 이상의 스타를 받아본 경험도 있습니다. 그런데 여태까지 제가 스타를 받아왔던 방식과는 근본적으로 조금 다르다는 생각이 들었습니다.

### 알아서 찾아올수가 없다

제가 기존에 오픈소스로 스타를 받아왔던 프로젝트들은 홍보를 했다기 보다는 사용자분들이 알아서 찾아왔습니다. (홍보를 조금 하긴 했지만요) 대표적으로 [한국어 음성인식 프로젝트](https://github.com/sooftware/kospeech)와 [Conformer 구현체](https://github.com/sooftware/conformer)가 있습니다. 한국어 음성인식을 하려는 유저들 입장에서는 인터넷 검색을 하다보면 제 프로젝트로 유입될 확률이 굉장히 높았고, Conformer는 구글에서 공개한 유명한 AI 모델 아키텍처인데, 이 역시 구현체를 찾는 사람들이 검색을 하다가 자연스럽게 제 프로젝트로 유입될 수 밖에 없는 구조였습니다. 하지만 이미 여러 좋은 터미널 앱이 넘쳐나는 상황에서 lmux가 눈에 띄기는 어렵고, 그렇다고 lmux라는 키워드를 검색해서 들어올 사람들은 더더욱 없습니다.

### 그래서 홍보했습니다

그래서 유저들이 유입될 수 있게 홍보를 시작했습니다. 
  
- [Reddit](https://www.reddit.com/)
- [Product Hunt](https://www.producthunt.com/)
- [Hacker News](https://news.ycombinator.com/)
- [Geek News](https://news.hada.io/) (홍보 예정)
  
나름 해외 유저들을 겨냥해서 미국 기준으로 아침 8시 되는 시간에 맞춰서 글을 올려보기도 하고, Claude와 함께 홍보 문구를 어떻게 쓸지에 대해서 여러 방면으로 고민하기도 했습니다. 레딧와 해커뉴스 모두 새로 가입한 유저의 글은 눈에 띄기가 어려워서 홍보하는데 한계를 느끼기도 했습니다. Geek News의 경우 계정 가입 한 달 후부터 글 쓰는게 가능해서 아직 못 쓰기도 했습니다. 직접 홍보를 하려다보니 막막한게 한두개가 아니더라고요.

## 마치며

lmux는 '내가 쓰는 터미널이 좀 더 가벼웠으면 좋겠다'는 생각 하나로 시작했습니다. 예전 같았으면 불편해도 그냥 참고 썼을 텐데, Swift를 거의 모르는 제가 Claude Code 덕분에 앱을 만들어서 배포까지 해봤습니다.
  

그리고 직접 앱 홍보도 해보면서, 100+개의 다운로드가 생겼다는거에 나름 소소한 만족을 느끼고 있습니다. 계속 써보면서 필요한 기능 하나하나 추가해가면서 이 100개의 다운로드가 1,000개, 10,000개로 쭉쭉 늘 수 있도록 해보려고 합니다!
  

Claude Code나 Codex를 멀티 세션으로 쓰시는 Mac 유저분들은 한 번 써보시고, 불편한 점이나 버그가 있으면 편하게 이슈 남겨주세요. 마음에 드셨다면 star도 부탁드립니다!

```sh
brew install --cask sooftware/tap/lmux
```

> macOS 14 이상, Apple silicon에서 동작합니다.

이상으로 글을 마치겠습니다. 읽어주셔서 감사합니다!
